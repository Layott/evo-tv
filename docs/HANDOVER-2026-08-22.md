### What shipped: PR #247, `feature/geoip-on-the-droplet`

`lib/geo/ip-location.ts` asks three sources in order of what each costs:

1. **Cloudflare headers** when the request came through the proxy. Free.
2. **A local city database**, no network, no third party. Covers what
   Cloudflare never saw, which on `api.` is everything.
3. **IPinfo**, one HTTPS call, only for addresses the local file places in a
   country but not a city.

Cached a day per address, so a viewer heartbeating every fifteen seconds costs
one lookup a day rather than 5,760. Every step is optional: with no file and no
token it returns null and callers degrade to exactly the old behaviour. It
**never throws**, because no location is an acceptable outcome inside a sign-in
and an exception is not.

Wired into `recordLoginEvent` and the viewer heartbeat. `/api/edge/whereami`
now reports all three sources rather than only Cloudflare.

## Which database, settled by measuring

I told the owner GeoLite2 was "generally sharper on mobile networks". Then the
owner made a MaxMind account and I measured both against 17 real addresses,
mostly Nigerian mobile ranges. **That claim did not hold.**

| | DB-IP City Lite | MaxMind GeoLite2 |
|---|---|---|
| named a city | **17 of 17** | 10 of 17 |
| `105.112.0.1` Airtel NG | Ikenne, Ogun State | NG only |
| `41.190.3.1` NG broadband | Lekki, Lagos | NG only |
| `8.8.8.8` | Mountain View, California | US only |
| `1.1.1.1` | Sydney, New South Wales | nothing |

GeoLite2 abstains where it is unsure, which is a defensible design. But here
**every abstention becomes an IPinfo call**, and IPinfo has a monthly allowance
where a local file has none. DB-IP stays the default.

DB-IP errs the other way: it labels ranges down to a neighbourhood, mobile
ranges included, e.g. "Lagos (Victoria Island Annex)", "Lekki (Banana Island)".
**A handset is wherever the carrier's gateway is not**, so that district is a
precision the data does not have, and an operator reading it in the audit log
would believe it. `trimLocality` stores the city and drops the parenthetical.

Coverage is not accuracy, and this sample cannot prove accuracy without ground
truth. What it does prove is that the assumption behind the recommendation was
wrong, which is why the file on the droplet did not change.

**The MaxMind key exists and is unused.** Setting `MAXMIND_LICENSE_KEY` in
`/srv/evotv/.env` switches `geoip-refresh.sh` to GeoLite2 on the next run. It
is deliberately not set. Account 1397953.

## Bounding the IPinfo spend

The owner proposed calling IPinfo only on each user's **first and last sign-in
per day**. Right concern, unworkable rule: **which sign-in was the last is not
knowable when the row is written**, so it needs a nightly pass to fill rows in
afterwards. Two changes instead, both tighter:

- **`remote` is opt-in and only the sign-in path passes it.** Heartbeats are
  the volume, tens of thousands a day against a handful of sign-ins, and they
  store the country alone, which the local file gives for effectively every
  address. So heartbeats never call out, and **every** sign-in is still located
  rather than one or two per person per day.
- **A daily ceiling counted in Valkey**, `IPINFO_DAILY_MAX`, default 1,000.
  Shared, because two api containers each holding their own would permit twice
  the number. Over the line it logs once and uses the local file.

Expected steady-state IPinfo volume: near zero, since DB-IP named a city for
17 of 17 sampled addresses and only a miss triggers a call.

# SEO and structured data

Merged as PR #251 -> #252 -> #253, production main `7637b32`.

## The blocker nobody had named

**19 of the public pages are client components, and a file with `"use client"`
can never export `metadata`.** That is the whole reason 94 pages shared one
title and one description, which search engines collapse into a single result.

The fix is a `layout.tsx` per segment: a layout is a server component, so it can
carry `generateMetadata` and render JSON-LD while the page underneath stays a
client component. **No page file was touched**, which is what makes the "does
not change the design" claim checkable rather than hopeful.

## What ships

| | before | after |
|---|---|---|
| distinct titles | 9 public pages | every public page |
| canonicals | missing on /shows, /apps, episodes | everywhere indexable |
| structured data | none | 10 types |
| sitemap URLs | 3 fixed + registry shows | database-driven |
| agents named in robots | 0 | 18 |

`noindex` on `(auth)`, `(authed)`, `(embed)`, `/home` and every ComingSoon page.
`/home` because it is the signed-in shell `/` redirects to, and indexing both
would put two near-identical results in front of one search.

## Rules the builders enforce

- **A field we do not have is omitted, never invented.** `isoDate` treats the
  epoch as absent, because `toEpisode` fills a missing `releasedAt` with
  `new Date(0)`: publishing it would tell every crawler these shows came out in
  1970. A sentinel meaning "unset" becomes a false fact the moment it ships.
- **No `aggregateRating`.** There are no ratings; inventing them is fabricating
  evidence at scale and is a manual-action offence.
- **No `SearchAction`.** The header search goes to `/discover`, which takes no
  query parameter. Add it when `/discover?q=` works and not before.
- **Prices match checkout**, and a product with variants emits an
  `AggregateOffer` range rather than quoting the base price for a shirt whose
  XL costs more.

## Three landmines

1. **`app/sitemap.ts` is prerendered during `next build`.** The droplet builds
   in Docker with no database reachable, so reading six tables without
   `force-dynamic` would have failed the image build exactly as `app/page.tsx`
   once did.
2. **Tailwind `space-y-*` compiles to `& > :not([hidden]) ~ :not([hidden])`.**
   A `<script>` counts as a sibling and would push a margin onto the first
   visible child. The blocks carry `hidden` so they cannot.
3. `/shows`, `/apps` and the episode route were **indexable with no canonical**,
   so a link shared with `?utm_source=` split the ranking with the real page.

## Design proof

The `/upgrade` layout fingerprint, 25 elements with their widths and heights,
is **byte identical** between production (old code) and the new build. Only the
tab title differs. A screenshot is a judgement call; this is not.

# The SEO rule, enforced

PRs #255 -> #256 -> #257, production main `1abeb04`.

Owner asked for SEO to work the way the audit rule works: not remembered, but
enforced. `scripts/seo-coverage.mjs` runs inside `pnpm check` at `--max 0`, and
the rule is in `backend/CLAUDE.md`.

## The distinction that matters

**Adding content needs nothing.** A new show, VOD, clip, event, team or product
is described automatically, because the routes carry `generateMetadata` and
JSON-LD and the sitemap reads the tables. Publishing a show puts `/show/<slug>`
in the sitemap with a `TVSeries` block on the next request.

The rule guards **new kinds of page**, which is the case that needs a human.

## What it checks

Metadata exists on the page or on a layout **inside the same route**, not the
site default. An indexable page has a title, a description and a canonical. A
ComingSoon screen is noindex. An entity route renders JSON-LD. Every indexable
route has rows in `sitemap.ts`. And the private groups are checked from the
other end: `(auth)`, `(authed)`, `(embed)` must be noindex at the group layout.

Exceptions live in `SITEMAP_EXEMPT` / `JSON_LD_EXEMPT` **with a reason written
next to them**.

## It found two real gaps immediately

`/clips/[id]` and `/stream/[id]` were indexable, carried `VideoObject`, and were
in no sitemap. Fixed rather than exempted. Clips newest first; **streams only
while live**, deliberately: the watchable version of a broadcast that ended last
Tuesday is the VOD, and the 24/7 channel is always live so it is always listed.

## 🚩 Two bugs in the checker, both of which made it pass everything

Worth recording because a checker that reports a clean site is worse than no
checker: it converts an unknown into a false assurance.

1. **It matched a dynamic route against its static prefix**, so `/clips/[id]`
   was satisfied by the `/clips` entry that lists the page *of* clips. Every
   individual clip was missing and the check was green. A dynamic route now has
   to be matched by a template that interpolates.
2. **It decided noindex by searching the file for `noIndex`**, and every dynamic
   layout carries `if (!clip) return pageMetadata({ noIndex: true })` for a
   record that does not exist. So the string appears in a file describing a page
   that is very much indexed, and the title, canonical, JSON-LD and sitemap
   checks were skipped on **every entity page on the site**. A route now counts
   as noindex only when there is no indexable path through it.

This is the second time in two days a checker needed checking; the audit
coverage script had the same class of fault (`before:` vs `before,`).
**Prove a checker by making it fail on purpose.** Three throwaway pages were
added, each producing the specific message it should, then deleted.
