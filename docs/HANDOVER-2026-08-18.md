## 1. The live stream stopped buffering (the big one)

The owner reported buffering repeatedly. The player was tuned first and it still
buffered, so the origin was measured instead of guessed at again.

**Root cause, measured against the live broadcast:** one rendition at **2,667
kbps** with no ABR ladder, so a viewer who could not hold 2.7 Mbps had nothing to
fall back to. Confirmed separately that `api.evotv.co` resolves straight to the
droplet (`Via: 1.1 Caddy`, no `cf-*` headers), so there is no CDN in front of the
video either.

### The ladder, now live

Three rungs in `deploy/nginx-rtmp.conf`, with the twin at
`infra/nginx-rtmp/nginx.conf` kept in step. Measured on air:

| Rung | Actual | Advertised |
|---|---|---|
| `_low` 640x360 | 647 kbps | 1,000,000 |
| `_mid` 854x480 | 1,318 kbps | 1,800,000 |
| `_hi` 1280x720 | 1,681 kbps | 3,200,000 |

**Worst-case viewer went from a forced 2,782 kbps to 647, a 4.3x cut.**

The box does **not** transcode. nginx repackages what the office encoder sends,
which is the only reason self-hosting beats a per-minute CDN here. Encoder
settings are in `docs/RUNBOOK-quality-ladder.md`. Never add `exec ffmpeg` to the
nginx config.

### Three app-side consequences, none optional

- The stream row stores the **master** playlist, so the publish name has its rung
  suffix stripped (`baseStreamName`). Storing `<id>_hi.m3u8` would pin every
  viewer to the top rung.
- Three publishes are one broadcast, or one show becomes three schedule rows.
- `on-publish-done` fires per rung, so `_low` is the rung that means "off air":
  cheapest to sustain, last to fail.

### Player changes

- Live now banks **8 seconds** before showing the first frame, and sits ~20s off
  the edge. `canplay` fires with about one frame decoded, which is why playback
  used to start with an empty buffer and stall immediately.
- **The `autoplay` attribute had to come off the element for live.** It starts
  the browser the moment bytes land, so it defeated the prebuffer gate entirely.
  Found by setting the threshold to ten minutes and seeing playback running at
  `readyState` 0.
- Scrub bar, skip buttons and the "0:26 behind / Go live" readout are gone **on
  live only**. They all move a viewer off the edge, which is what the cushion is
  for. Recorded video keeps all three.

### Bug found on the way

`on-publish-done` hashed `name` as the key, but publishing moved to
`<streamId>?key=<secret>` some time ago, so the hash matched nothing and **every
ended broadcast left its row `is_live = true` forever**.

### Still open

Every viewer pulls from one droplet in Frankfurt. **Do not propose Cloudflare
Stream:** the owner rejected it on 2026-08-16 because it bills per delivered
minute with no cap, and a recommendation from stale memory had to be retracted
mid-signup. See `docs/DECISION-live-streaming.md`, top of file.

## 2. Encoder setup, and the traps that cost hours

The office runs **OBS 32.1.2** on an RTX 3060.

- `obs-multi-rtmp` will not load on OBS 32. **Aitum Multistream** is the one that
  works.
- Aitum's outputs failed to start with **no error in the UI**. The OBS log had
  it: `NV_ENC_ERR_INCOMPATIBLE_CLIENT_KEY`. Read the OBS log first.
- That error was **not** a missing driver. 591.86 was installed and the machine
  had never rebooted, so the kernel still had 581.95 loaded, too old for OBS 32's
  NVENC SDK. `PendingFileRename` in the registry is the tell.
- Aitum honours **resolution** but ignores **bitrate** and **keyframe interval**.
  It sent 6.4 Mbps on a rung set to 400 kbps. Verify with ffprobe and by dividing
  segment bytes by `EXTINF`, never by trusting the settings dialog.
- **`BANDWIDTH` in the master playlist comes from the nginx config, not from the
  stream.** nginx does not inspect what arrives, so an overshooting encoder makes
  the playlist lie to players, which is worse than no ladder. Re-measure whenever
  encoder settings change.

**Owner action outstanding:** reboot the office machine to load 591.86, then move
all three rungs onto NVENC.

## 3. Security: the VOD paywall was decoration

Every public endpoint returning a VOD put `hlsUrl` and `mp4Url` in the JSON
regardless of `isPremium`, so the subscription wall came off with devtools and a
copy-paste. The sweep found **four** endpoints leaking premium video, plus
`/api/feed/home` leaking **live stream manifests** to signed-out callers, which
the existing stream stripper had missed entirely.

Now enforced in `lib/api/playback.ts`. **Watching requires an account** (owner's
decision, 2026-08-18), free rows included, and premium rows additionally require
a subscription. Verified on all four paths against a real premium row.

Note: my first cut gated premium only and was corrected; then the owner asked for
the whole catalogue to require sign-in. The VOD page has its own sign-in overlay,
deliberately not the premium one reworded.

## 4. Everything else shipped today

- **APK: 96.6 MB to 55.5 MB.** `expo prebuild` writes all four ABIs and the two
  x86 ones are emulator-only, so **43% of the download could not run on a
  phone**. Patched in `scripts/build-apk-local.ps1`, because `prebuild --clean`
  regenerates `gradle.properties`. R8 deliberately left off (dex is 15.1 MB, so
  there is more to win, but minifying RN breaks reflection-based native modules
  and fails as a crash in release, not at build time).
- **Chat.** `sendMessage` returned the `{ message }` wrapper as if it were the
  message, so a just-sent line **turned blank and attributed to "viewer"**, and
  the SSE echo was **duplicated** because the dedupe compared `undefined` against
  a real id. One bug, all three reported symptoms. Transport was verified end to
  end on prod before anything was changed.
- **Streams are editable.** Title, description, streamer, event, tier and
  thumbnail. Slug is left alone on rename so shared links keep working.
- **Stream thumbnails on create.** The route hardcoded `thumbnailUrl: ""` and the
  form had no field.
- **Web admin stream parity.** Five controls the app had and the web did not: End
  broadcast, Maturity rating, Playout file, the Deleted view, and Restore. All
  already accepted by the API.
- **Home page comes on air by itself.** The hero polled every 60s.
  `on-publish` already emitted `stream:live-now` and nothing on the web listened;
  `sseStream` existed and had never been used. New `/api/sse/channel`.
- **API keys screen** now exists at `/api-access/keys` (was ComingSoon while the
  endpoints had been live for months). Create, list, revoke.
- **Publishing an APK works.** It never had: the presign rejected the
  `downloads/` prefix, and once past that the object landed **private and 403'd**
  because Spaces ignores the ACL unless `x-amz-acl` is sent as a header.
- **App admin Sections button.** It is mounted via `headerRight`, which renders
  into the **native** stack header, and an RN `Modal` cannot mount there. Created
  and never displayed, nothing thrown. **Unverified on device**; needs the owner
  to press it on build 225.

## 5. Landmines

- **`resize_window` lies on a maximized window.** Use `phone-harness.mjs` on 4747
  for a real 390x844 viewport.
- **Chrome will not load media in a hidden tab.** Playlists fetch, segments do
  not, and the player sits at `readyState` 0. Every buffer measurement has to
  come from a foreground tab or from `curl`.
- **Stale Turbopack builds.** A route returning 405 with correct source, or an
  edit that will not apply, means `rm -rf .next` and restart. Cost two separate
  debugging detours today.
- **The `{ wrapper }` vs value bug bit twice.** `sendMessage` (fixed) and
  `adminUpdateStream`, which is still *typed* `Promise<{ stream: Stream }>` while
  the route answers a flat `{ ok, streamId, ... }`. Check the route's actual
  `NextResponse.json(...)` before trusting a client function's type.
- **Better-Auth caches role in the session cookie.** Promoting a user in the DB
  does not affect an existing session; sign in again.
- **`deleted_at` is stored as text**, so comparisons need `::timestamptz`.
