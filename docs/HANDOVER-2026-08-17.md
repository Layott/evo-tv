#### The one thing that matters

Make the token **transparent, not fainter**. A quieter hairline is still a hairline, and the token is the only edit that reaches ~300 (web) and ~325 (app) call sites at once.

- web: `app/globals.css`, the brand override block near line 398. **Not** the shadcn `:root` / `.dark` blocks near lines 23 and 59 - those still hold the stock oklch greys and are overridden later.
- app: `tailwind.config.js` and `lib/theme/tokens.ts`, both, they drift.

`--input` / `input` stays visible at `#17454A` deliberately. A form field with no edge cannot be found. The one border still painting in production is the `/shop` sort `<Select>` trigger, and that is correct.

#### What the token does NOT reach

This is where the actual work was. Four categories survive a token change:

1. **59 inline `borderWidth` + `borderColor` styles in the native app.** RN inline styles bypass Tailwind. Two codemods handled these; the second one deals with multi-line and conditional values.
2. **`ring-1` / `ring-2`.** A ring is a hairline. Converted to fills. **`focus-visible:` rings stay** - the ban explicitly keeps the accessibility affordance.
3. **`border-input` on things that are not form controls.** It had leaked onto badges, chips and thumbnails, and it is a real colour, so it survived the `--border` change untouched.
4. **`Button` and `Badge` `outline` variants** in `components/ui/`. Filled now. The variant name lies; the shape is right.

#### The conversion rule

A tinted 10% wash held together by a 30% ring becomes a **flat 25% fill with lighter text** (`text-<hue>-300` -> `-100`). Same visual weight, no line.

Where a ring was the only thing marking state it had to be **redesigned, not deleted**: selection by fill on the onboarding cards and the theme and quality pickers, the tick box filled in both states rather than an outline around nothing when unticked, the follow button a muted fill, the clip hover a wash. The admin colour swatches show a tick **inside** the chip, because a swatch's fill is the value it stands for and cannot also be its selection.

A border painted in the page background (`#05191B`) is a **gap between stacked elements, not a line**. Avatar rings and the notification unread dot keep theirs on purpose.

#### Glow

Banned the same day by the owner's second hard rule. Removed all 58 `animate-pulse`: live and status dots are solid and still, skeleton placeholders are a static muted surface. Also gone: the admin status dot's `shadow-[0_0_6px_currentColor]`, and the paywall's `blur-3xl` sky-blue orb plus its `shadow-sky-500/10`. Elevation there is neutral black now.

#### How it was verified

`verify-design.mjs` (session scratchpad): real Chrome, signed in, **1440x950 and 390x844**, counting elements whose *computed* style actually paints a border, a zero-offset coloured shadow, or a pulse animation.

Counting computed style rather than grepping class names is the point: a class name cannot tell you whether a border paints, and after a token change almost none of them do.

The owner added it to both `CLAUDE.md` files partway through this session, sourced from an aj.on.ai reel. Test: *if a stranger can tell an LLM generated the UI in 3 seconds, it is wrong.* **Audited, not acted on.**

Two hits need owner direction rather than a guess, because the rule itself says to ask:

- **Typeface.** `app/layout.tsx` loads `Geist`, `Geist_Mono` and `Bricolage_Grotesque`. The rule bans Geist as a default face. Bricolage is already doing the display work, so the open question is the body and mono pairing.
- **Icons.** Stock Lucide across both repos, which the rule names directly.

One violation was introduced by this very session and should be fixed first: the `/upgrade` highlighted plan card is now `bg-gradient-to-br from-sky-500/25 via-card/60 to-amber-500/20`, a multi-hue sweep, which rule A bans.

Also unresolved from the rule's "required" list: `/upgrade` is a tier ladder, and rule B bans the three-tier pricing table shape.
