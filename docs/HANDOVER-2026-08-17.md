#### The one thing that matters

Make the token **transparent, not fainter**. A quieter hairline is still a hairline, and the token is the only edit that reaches ~300 (web) and ~325 (app) call sites at once.

- web: `app/globals.css`, the brand override block near line 398. **Not** the shadcn `:root` / `.dark` blocks near lines 23 and 59 - those still hold the stock oklch greys and are overridden later.
- app: `tailwind.config.js` and `lib/theme/tokens.ts`, both, they drift.

`--input` / `input` stays visible at `#17454A` deliberately. A form field with no edge cannot be found. The one border still painting in production is the `/shop` sort `<Select>` trigger, and that is correct.

#### What the token does NOT reach

This is where the actual work was. Four categories survive a token change:

1. **59 inline `borderWidth` + `borderColor` styles in the native app.** RN inline styles bypass Tailwind. Two codemods handled these; the second one deals with multi-line and conditional values.
2. **`ring-1` / `ring-2`.** A ring is a hairline. Converted to fills. **`focus-visible:` rings stay** - the ban explicitly keeps the accessibility affordance.
3. **`border-input` on things that are not form controls.** It had leaked onto badges, chips and thumbnails, and it is a real colour, so it survived the `--border` change untouched.
4. **`Button` and `Badge` `outline` variants** in `components/ui/`. Filled now. The variant name lies; the shape is right.

#### The conversion rule

A tinted 10% wash held together by a 30% ring becomes a **flat 25% fill with lighter text** (`text-<hue>-300` -> `-100`). Same visual weight, no line.

Where a ring was the only thing marking state it had to be **redesigned, not deleted**: selection by fill on the onboarding cards and the theme and quality pickers, the tick box filled in both states rather than an outline around nothing when unticked, the follow button a muted fill, the clip hover a wash. The admin colour swatches show a tick **inside** the chip, because a swatch's fill is the value it stands for and cannot also be its selection.

A border painted in the page background (`#05191B`) is a **gap between stacked elements, not a line**. Avatar rings and the notification unread dot keep theirs on purpose.

#### Glow

Banned the same day by the owner's second hard rule. Removed all 58 `animate-pulse`: live and status dots are solid and still, skeleton placeholders are a static muted surface. Also gone: the admin status dot's `shadow-[0_0_6px_currentColor]`, and the paywall's `blur-3xl` sky-blue orb plus its `shadow-sky-500/10`. Elevation there is neutral black now.

### Admin analytics, overview, and the missing usernames

#### Usernames and avatars were four bugs, none of them the data

1. `/api/admin/users` **never joined `profiles`**, the table that holds the
   display name, uploaded avatar, bio and country. It returned raw Better-Auth
   `user` columns while the table renders `displayName` / `avatarUrl`, and the
   client typed the result `Profile[]` **without mapping**, so the cast compiled
   and every field arrived `undefined`. Now joins and maps through `toProfile`,
   the same mapper the public profile pages use.
2. Search sent `q`; the endpoint reads `search`. It also could not match on name.
3. "Last active" was the signup date relabelled. Now the newest login event, or
   "Never signed in".
4. **`localStorage.write` returned the bare key** while the Spaces adapter
   returns a full URL, and both callers persist it into an `<img src>`. Prod was
   fine; any checkout without `SPACES_KEY` stored unusable paths.

#### Per-video analytics

Nothing recorded playback **position** before this. `episode_progress` and
`vod_progress` keep the latest position per viewer, which describes the
survivors and says nothing about who left; `watch_events` is minute buckets
against a live channel, not a title.

Migration **0040** adds `video_view_buckets`, one row per **(video, session,
percent reached)**. Bounded to 100 rows per viewer per video, re-watching
collides on the PK and is free, and every figure falls out of it:

| metric | derivation |
|---|---|
| views | `count(distinct session_id)` |
| watch time | `count(*) * duration / 100` |
| avg % viewed | avg over sessions of `max(bucket) + 1` |
| retention | per bucket, sessions reaching **at least** it / views |

`hooks/use-watch-heartbeat.ts` beats **at least once per percent of runtime**,
clamped 2-10s. A fixed 10s beat undercounts watch time badly on short videos.

**Two traps, both found by testing rather than reading:**

- Retention must be **cumulative** (from each session's furthest point). Counting
  beats that land exactly in a bucket gives `100, 0, 100, 0`, because the player
  beats on a timer, not once per percent.
- **Day keys must be UTC at both ends.** Local midnight vs the DB timezone put
  today outside the range; the chart totalled 0 beside a headline of 24.

#### Overview

## Type and icons, both repos

Owner picked **Archivo** (from four candidates rendered as real product UI at
desktop and 390px) and **Phosphor at fill weight**.

Archivo carries a real `wdth` axis, which is what earned it the job: a headline
sets wide like a scoreboard, the same family runs at normal width for 12px table
text. `axes: ["wdth"]` on the `next/font` call is load-bearing. Without it
next/font ships the weight axis alone and every `font-variation-settings`
silently does nothing. Bricolage is gone; two unrelated families was the wrong
shape, since the admin CMS and the channel headline had nothing in common.

Phosphor, not just because the rule names Lucide, but because **every Lucide
glyph is a 2px open stroke**. After the hairline ban took the lines out of
cards, chips and dividers, the icons were the last place still building shapes
from thin strokes. `components/icons/` in both repos is a shim exporting
Phosphor under the Lucide names, so 104 web files and 86 app files changed one
import line. Weight by what the glyph is: `fill` for objects and states, `bold`
for glyphs that are inherently a line, because a filled arrow is a blob.

Import from `@phosphor-icons/react/dist/ssr` on the web. The main entry reads
`IconContext` through `useContext`, which would force `"use client"` onto server
pages that render nothing but an icon.

Sparkles, Star and Crown are not in either shim. Sixteen web and sixteen app
call sites were using them as decoration meaning "premium", so each got the icon
that names what it does. **Star survives in the app in one role only: a rating
beside a number**, which is what a star has always meant.

`lucide-react` and `lucide-react-native` are both uninstalled, so an import
cannot quietly come back.

### The app had never loaded a font at all

`components/providers/font-loader.tsx` was a stub returning `{loaded: true}`
that required nothing. Every screen has been on the system face while
`tailwind.config.js` claimed Geist and two navigators asked for
"GeistSemiBold".

Three attempts, and **only measuring found the first two were no-ops**:

1. `Text.defaultProps` is the recipe everywhere online and does nothing. React's
   automatic JSX runtime, which Expo uses, does not resolve `defaultProps`.
2. Patching `Text.render` to clone the returned element also does nothing: by
   then react-native-web has compiled the style into atomic classes and handed
   back a plain `div`, which will not take an RN style array.
3. Patching the props going in works, on native only. On web it is actively
   wrong: NativeWind passes `className` straight to the DOM, so the injected
   style becomes an atomic class that outranks the weight rules, and every
   heading dropped back to regular weight. Web gets its default from
   `global.css` instead.

Each weight is its own registered family because RN does not synthesise weights
on Android. `global.css` redefines `font-medium` / `font-semibold` / `font-bold`
to carry the family too, so 529 existing class sites did not change.

The display face is two local `.ttf` files, instanced from Google's CSS endpoint
at exactly `wdth` 118, the width the web sets headings at.
`@expo-google-fonts/archivo` ships weights only and RN cannot reach a variable
font's axes.

## The two landmines

**`ALLOWED_ORIGINS=*` 403.** `lib/auth/index.ts` filtered `*` out of the list,
leaving it empty, which fell back to Better-Auth's `[baseURL]` default, the one
value guaranteed not to be the origin the wildcard was set for. Meanwhile
`proxy.ts` had always read `*` as "reflect whatever asked", so CORS passed and
the sign-in itself answered 403, which reads as a wrong password. Fixed, and
**refused in production**: `trustedOrigins` is also the OAuth callbackURL
allowlist, so a wildcard there is an open redirect. Proven end to end: sign-in
from `localhost:8090` now returns 401 "Invalid email or password", not 403.

**Stale Turbopack build.** `watchOptions.pollIntervalMs` is real and Turbopack
does read it (`hot-reloader-turbopack.js` passes it to `createProject`), but it
did **not** work. Rewriting `/upgrade` and reloading served the previous
version, no chunk contained the new text, and the server had logged **zero**
compiles all session. Touching the file changed nothing.

`scripts/dev-stale-guard.mjs` now takes the newest mtime across app, components,
lib, db, hooks, styles plus the config files, and the file count so deletions
register. Anything newer than the build and `.next` goes before Turbopack can
serve from it. A cold start here is 415ms.

## Mobile verification works now, for the first time

Recorded as an open blocker since 2026-08-12. Three stacked problems:

1. `resize_window` returns "Successfully resized" on a **maximized** window and
   does nothing, so every past "resized to 390 and screenshotted" was a 1920px
   render with a success message.
2. Un-maximizing needs an OS-level `EnumWindows` sweep over
   `Chrome_WidgetWin_1`; the window holding the tab is not the one
   `Get-Process` reports as main.
3. Chrome on Windows will not go below about 500px wide regardless.

`scratchpad/phone-harness.mjs` frames any URL in a 390x844 iframe, which gives
the document a genuine 390px CSS viewport: media queries fire and
`useWindowDimensions` reports 390.
