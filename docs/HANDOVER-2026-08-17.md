#### The one thing that matters

Make the token **transparent, not fainter**. A quieter hairline is still a hairline, and the token is the only edit that reaches ~300 (web) and ~325 (app) call sites at once.

- web: `app/globals.css`, the brand override block near line 398. **Not** the shadcn `:root` / `.dark` blocks near lines 23 and 59 - those still hold the stock oklch greys and are overridden later.
- app: `tailwind.config.js` and `lib/theme/tokens.ts`, both, they drift.

`--input` / `input` stays visible at `#17454A` deliberately. A form field with no edge cannot be found. The one border still painting in production is the `/shop` sort `<Select>` trigger, and that is correct.

#### What the token does NOT reach

This is where the actual work was. Four categories survive a token change:

1. **59 inline `borderWidth` + `borderColor` styles in the native app.** RN inline styles bypass Tailwind. Two codemods handled these; the second one deals with multi-line and conditional values.
2. **`ring-1` / `ring-2`.** A ring is a hairline. Converted to fills. **`focus-visible:` rings stay** - the ban explicitly keeps the accessibility affordance.
3. **`border-input` on things that are not form controls.** It had leaked onto badges, chips and thumbnails, and it is a real colour, so it survived the `--border` change untouched.
4. **`Button` and `Badge` `outline` variants** in `components/ui/`. Filled now. The variant name lies; the shape is right.

#### The conversion rule

A tinted 10% wash held together by a 30% ring becomes a **flat 25% fill with lighter text** (`text-<hue>-300` -> `-100`). Same visual weight, no line.

Where a ring was the only thing marking state it had to be **redesigned, not deleted**: selection by fill on the onboarding cards and the theme and quality pickers, the tick box filled in both states rather than an outline around nothing when unticked, the follow button a muted fill, the clip hover a wash. The admin colour swatches show a tick **inside** the chip, because a swatch's fill is the value it stands for and cannot also be its selection.

A border painted in the page background (`#05191B`) is a **gap between stacked elements, not a line**. Avatar rings and the notification unread dot keep theirs on purpose.

Also gone: the admin status dot's `shadow-[0_0_6px_currentColor]`, and the paywall's `blur-3xl` sky-blue orb plus its `shadow-sky-500/10`. Elevation there is neutral black now.

### Admin analytics, overview, and the missing usernames

PR [#10](https://github.com/Layott/evo-tv/pull/10) -> `dev`. **Not on prod yet.**

#### Usernames and avatars were four bugs, none of them the data

1. `/api/admin/users` **never joined `profiles`**, the table that holds the
   display name, uploaded avatar, bio and country. It returned raw Better-Auth
   `user` columns while the table renders `displayName` / `avatarUrl`, and the
   client typed the result `Profile[]` **without mapping**, so the cast compiled
   and every field arrived `undefined`. Now joins and maps through `toProfile`,
   the same mapper the public profile pages use.
2. Search sent `q`; the endpoint reads `search`. It also could not match on name.
3. "Last active" was the signup date relabelled. Now the newest login event, or
   "Never signed in".
4. **`localStorage.write` returned the bare key** while the Spaces adapter
   returns a full URL, and both callers persist it into an `<img src>`. Prod was
   fine; any checkout without `SPACES_KEY` stored unusable paths.

#### Per-video analytics

Nothing recorded playback **position** before this. `episode_progress` and
`vod_progress` keep the latest position per viewer, which describes the
survivors and says nothing about who left; `watch_events` is minute buckets
against a live channel, not a title.

Migration **0040** adds `video_view_buckets`, one row per **(video, session,
percent reached)**. Bounded to 100 rows per viewer per video, re-watching
collides on the PK and is free, and every figure falls out of it:

| metric | derivation |
|---|---|
| views | `count(distinct session_id)` |
| watch time | `count(*) * duration / 100` |
| avg % viewed | avg over sessions of `max(bucket) + 1` |
| retention | per bucket, sessions reaching **at least** it / views |

`hooks/use-watch-heartbeat.ts` beats **at least once per percent of runtime**,
clamped 2-10s. A fixed 10s beat undercounts watch time badly on short videos.

**Two traps, both found by testing rather than reading:**

- Retention must be **cumulative** (from each session's furthest point). Counting
  beats that land exactly in a bucket gives `100, 0, 100, 0`, because the player
  beats on a timer, not once per percent.
- **Day keys must be UTC at both ends.** Local midnight vs the DB timezone put
  today outside the range; the chart totalled 0 beside a headline of 24.

#### Overview

Chart plotted `day`; the endpoint returns `date`, so the **x-axis was blank on
every load**. The "Alerts" panel wrapped an empty array in a titled box,
permanently. Rebuilt on one endpoint (was four, two of which pulled 50 rows to
show 5), with computed alerts that only appear when something is wrong.
