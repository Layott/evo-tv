# Handover, 2026-08-15

The dashboard went from a screen that could read the platform to one that can
run it. Everything below is on `feature/admin-cms`, cut from `dev`.

## Where the branches sit now

The repo follows `feature/* -> dev -> staging -> main` from today.

| Branch | What it is |
|---|---|
| `main` | Production. The droplet's `autodeploy.sh` polls **this** branch and nothing else, so pushing a feature branch cannot reach viewers. |
| `staging` | Cut from `main`. Dress rehearsal. |
| `dev` | Cut from `feat/digitalocean`, which was the real development line since the DigitalOcean move. |
| `feature/admin-cms` | This work. |

`feat/digitalocean` is left where it is rather than renamed, because it is
already pushed and other machines may have it. `dev` is the same commit.

## Two bugs worth knowing about

Both were the same mistake, and both were found by signing in as a head admin
rather than by reading the code.

1. **`AdminGuard` tested `role !== "admin"`.** That is true for a `head_admin`,
   so the highest role on the platform could not open a single page of the
   dashboard it owns.
2. **`requireAdminFromRequest` did the same.** Every admin write answered 403 for
   a head admin: creating a show, uploading a file, editing the catalogue.

Both now compare on the ladder. There is one comparison in the system,
`hasMinRole`, and the ladder is in `lib/auth/role-catalog.ts` (pure, so the
browser reads what the server enforces).

## What shipped

**Roles.** An admin can grant `admin`, never above it. The last top-level admin
cannot be demoted or deleted; that floor existed in code since 14 August, was
imported into the users route and called by nothing. It now runs on role
changes, bulk changes, grant-by-email and the account self-delete. The roster
screen offered three of the nine roles; it offers all of them, each with a line
saying what it reaches. Full map: `docs/ADMIN-CONTROL-LEVELS.md`.

**Shows CMS** (`/admin/shows`). Create a show, its seasons, its episodes, upload
the video on each, set what it costs. Per the owner's spec:

- No slug field. The URL is the title, reduced. Renaming a show moves its URL,
  and the old address stops working: that is the trade, and it is the rule
  across the site now.
- No status picker. Status is derived from the episodes and the grid
  (`lib/api/show-state.ts`). The one thing nobody can infer, whether a series has
  finished, is a date.
- Creator handle became a set of social links shown to viewers.
- Poster is portrait 2:3 at 800x1200 or better, hero is 16:9 at 1600x900 or
  better, both under 2 MB, checked before the upload starts.
- A paid show has a price ladder: from day N it costs X, and zero means free from
  then on.

**Schedule** (`/admin/schedule`). Programming picks a show from the catalogue
instead of typing a name. Migration 0038 turned the 31 distinct titles already
in the grid into shows and pointed all 169 active slots at them. Copy-day,
overlap warnings as you type, and the unprogrammed hours listed so a gap is
visible rather than discovered by a viewer.

**Library** (`/admin/library`). Videos and clips. `/api/admin/clips` had no
create route at all, so the clips rail could only ever be empty. A clip attaches
to a video, a show, or one episode of a show (migration 0037).

**Subscriptions** (`/admin/subscriptions`). Who is past the paywall, until when,
cancel and extend. Refunds stay in Paystack.

**Announcements** (`/admin/announcements`). One message to the notification list,
the app and the browser. Every channel existed; nothing could trigger one. The
preview counts the audience before anything is sent, because there is no unsend.

**Catalogue.** Games, teams, players and events are editable and deletable. PATCH
and DELETE were always there; the screen told operators they were not. Deleting
now refuses when anything still points at the row, naming what is in the way,
because `vods.game_id` and `clips.game_id` cascade.

**Light theme.** 1,760 hardcoded neutrals across 110 files mapped onto semantic
tokens. Verified in a browser, which had never happened.

**Landing header** stays on screen while scrolling.

## Verified, and how

- Every write path exercised against a real head-admin session: shows, seasons,
  episodes (including the duplicate-number 409 and tier inheritance), clips
  linked to an episode, EPG create/patch/delete, catalogue edit, the delete
  refusal, promote-by-email 404, announcement preview.
- Migrations 0036, 0037 and 0038 applied to the dev database. 31 shows backfilled
  from grid titles, 169 slots linked, 0 unlinked.
- Browser walk at 1920 and at 390 wide: shows, schedule (dropdown open),
  library, subscriptions, announcements, users, plus the mobile drawer. No
  horizontal page overflow at 390 (`scrollWidth` 375), tables scroll inside
  their own box.
- Light theme opened in a browser: paper ground, dark type, legible badges.

## Not verified, and open

- **Nothing is applied to production.** Migrations 0036 to 0038 have run against
  the dev (Neon) database only. `0038` backfills shows from grid titles, so run
  it when the prod grid is what you want the catalogue to start from.
- **Uploads were never exercised end to end.** The local checkout has no
  `SPACES_KEY`, so the picker fell back to the legacy Blob path and was not
  clicked through. The presign leg is unproven from a browser.
- **A push has still never been delivered to a device.** The send paths exist and
  `deploy/cron.sh` does schedule `reminders` every 15 minutes on the droplet, so
  this is now a question of whether that crontab line is installed and whether a
  device is registered, not of missing code.
- **`resize_window` does not work** in this Chrome setup: `innerWidth` stays
  1920. Mobile was verified by rendering the page in a 390px iframe, which drives
  real media queries. Anything relying on touch or the mobile user agent is still
  unproven.
- The dev server hung three times during this session, always after a large
  recompile, and had to be killed by PID. It is not a code fault, but it wastes
  minutes.
