### Two guard bugs, three instances, same mistake

`role !== "admin"` is true for a **head_admin**. It appeared in:

1. `AdminGuard` - locked head_admin out of every dashboard page
2. `requireAdminFromRequest` - 403 on every admin write
3. `app/(admin)/_layout.tsx` in the native app - bounced them to the home screen

All three compare on the ladder now. `lib/auth/role-catalog.ts` is the single
definition on the web; the app carries a copy in `lib/auth/roles.ts`, because the
repos are deliberately not coupled by a shared package.

The last-admin floor in `lib/api/admin-roster.ts` had been written on 14 August,
imported into the users route, and **called by nothing**. It now runs on role
changes, bulk changes, grant-by-email and account self-delete.

### Two deploy blockers, neither in the code

1. The droplet crontab deployed **`feat/digitalocean`**, not `main`. The script's
   default is `main`; the installed crontab overrode it.
2. The droplet's clone is **single-branch**. Its refspec only mapped the branch
   it was cloned from, so `git rev-parse origin/main` failed and `set -e` killed
   autodeploy **before its first log line**. It died in silence every two
   minutes. Fixed on the box and in `deploy/autodeploy.sh`.

**When checking a deploy, wait for the `deployed <sha>` line in the log.** The
droplet's `HEAD` moves at the start of a deploy, roughly two minutes before the
new code is serving. Checking `HEAD` is how I twice reported something live that
was not.

    ssh -i ~/.ssh/evotv_prod root@138.68.126.199
    grep evotv-autodeploy /var/log/syslog | grep -E '==>|deployed' | tail

## The CMS, as the owner specified it

- **No slug field anywhere.** A slug is derived from the name it belongs to.
  Renaming a show moves its URL and the old one stops resolving; that is the
  trade, taken deliberately over a URL that can disagree with the title.
- **Status is derived**, not picked: ended date, then an episode released in the
  last 45 days, then a live grid slot, else upcoming (`lib/api/show-state.ts`).
- **Scheduling picks a show from the catalogue.** Migration 0038 turned the 31
  distinct titles already in the grid into shows and linked all 169 active slots,
  so the dropdown was populated from the first minute.
- **Creator handle became social links**, shown to viewers.
- **Paid shows have a price ladder**: from day N it costs X, zero means free from
  then on. Three rows express "N800 for two days, N500 after, free after a
  fortnight".
- **Product deletion** removes the row only when nobody has ever ordered it.
  Otherwise it deactivates: `orders.items` is a jsonb snapshot holding
  `productId`, and deleting would orphan past orders.

### Standing rule: image fields state their size

Every upload field says what to upload. Specs live once in
`components/admin/media-upload.tsx`: poster 2:3 (1000x1500), hero 16:9
(1920x1080), thumbnail 16:9 (1280x720), product square (1200), logo square
(512), banner 3:1 (1500x500). Shape and a 2 MB ceiling are checked **before** the
upload starts, so a wrong file costs nothing. Any new image field gets a spec.

### The APK

`pnpm apk` builds a signed release locally, without EAS cloud quota. The script
encodes four traps that each cost an afternoon once: Windows MAX_PATH forcing the
build to `C:\Users\Sweez\evo`, Node 20 first on PATH, the two patches
`prebuild --clean` wipes, and a guard that refuses to finish if the release
signing config did not apply.

It failed twice today and both were the script's own fault, caught by its guards
rather than shipped:

1. Git rewrites the script to CRLF on checkout while Expo writes `build.gradle`
   with LF, so the exact anchors missed. Both sides are normalised to LF now.
2. Gradle died on **Java heap space**: prebuild sets 2 GB and
   `:app:collectReleaseDependencies` needs more, made worse by stale daemons
   holding memory. The script raises it to 4 GB and stops old daemons first.

**The APK built before the account move is deaf forever** - the old update URL is
baked into its manifest. The release keystore is local rather than EAS-managed,
so a rebuilt APK is signed with the same key and upgrades in place over it.

## Open, and honest about it

- **No APK is hosted anywhere.** "Get the app" still points at `/apps`, which has
  no download on it. Nobody can install the app from the site today.
- **Uploads have never been exercised end to end.** The local checkout has no
  `SPACES_KEY`, so the picker falls back to the legacy Blob path. The presign leg
  is unproven from a browser.
- **A push has never reached a handset.** The send paths exist and
  `deploy/cron.sh` schedules the reminder fan-out every 15 minutes, so this is a
  question of a registered device, not of missing code.
- **iOS has no distribution route** outside the App Store or TestFlight. Android
  self-hosting is viable; iOS is not, and no amount of engineering changes that.
- `/upgrade` still lists tiers nobody has confirmed are real.
- Design parity across ~90 pages, and i18n, remain the two large jobs. The token
  sweep is the groundwork for the first: every page reads its colours from one
  place now.
- `resize_window` does not work in this Chrome setup; `innerWidth` stays 1920.
  Mobile is verified by rendering the page in a 390px iframe, which drives real
  media queries. Anything relying on touch or the mobile user agent is unproven.
